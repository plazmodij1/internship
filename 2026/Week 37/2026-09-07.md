### Blockers:
<!-- Issue:
Solution/Status:-->
**Issue 1**: While setting up an Ansible script to populate Netbox, I encountered issues when connecting to the Netbox API. The initial issue was that Ansible container could not connect to the Netbox API. At first I tried to troubleshoot it myself, but I soon realised that I don't understand anything from the error, and I don't know how to troubleshoot it. So, I decided to use AI. Initially, it wanted me to make changes in the code, but since the code was pulled from the repository, I didn't go that route. After a bit of back and forth, it said the reason I am getting an error is because they are not on the same network. This makes sense, since the Ansible service is defined in my own `docker-compose.yml` file, and the Netbox is started in another Docker compose file since it is easier to run it by cloning the repository and using its Docker compose file. For a fix, I decided to create an additional Docker network and added it to both of the containers, with an extra variable   `External`, which tells Docker that this network is from outside of compose file project. But, while fixing this issue I realised that there was another problem. 

**Issue 2**: In the Git repository that I was provided with, the Ansible script was using default values for the variables such as `NETBOX_API`. After looking at the service definition for the Ansible container, I realised that it was calling environment variables from a `.env` file, but for some reason when the container deployed, those variables wouldn't actually get passed. So, I decided to remove the environment variables and just reference the file directly using a variable `env_file`. After applying this fix, the container finally ran and it populated the Netbox with dummy data:
