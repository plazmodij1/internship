### Progress:

Today I started working on creating the synchronization logic. Since for this sprint I just need a simple synchronization, I didn't focus on extra features such as webhooks for NetBox or checking what data was updated. I will just create a simple system which retrieves data from NetBox and Icinga, checks if the retrieved data from NetBox exists in Icinga, and if it doesn't, creates the appropriate monitoring hosts. For now, I only created the logic for getting data from NetBox and Icinga. For NetBox, I used Ansible playbooks which has a module built for NetBox by NetBox. The logic checks for devices which have the custom field "monitor" set to `True`. It then takes the IP address and the name of those devices and stores them in a dictionary. Then, the scripts connects to the Icinga and checks if there are monitoring hosts with the names extracted from NetBox. For Icinga API there wasn't a module in Ansible playbook so when I create the logic for creating objects, I will need to create the payloads myself. 
### Blockers:
<!-- Issue:

There weren't any big blockers. I had some initial issues with the APIs, because I didn't know how to connect to them and properly apply the filter for `monitor` custom field. Luckly, NetBox has a really good documentation which covers how to create request payloads and also which filters exists. This helped me and I managed to successfully test the API before creating the Ansible script. For Icinga it was much simpler because it adds device names in the URL, so for example if the device name was `server` the URL would look something like: `/v1/objects/hosts/server/`.
