Fixed issues with the  original icinga repository plus added a bit of security. The following bugs were fixed:
Bug 1. In `docker-compose.yml`, the service for initialising the database was not getting the variable `ICINGAWEB_ICINGA2_API_USER_PASSWORD`. This was a problem, because if I wanted to declare a custom password for the API, it wouldn't get passed to the initialization script, hence the database would be using the default value. This would be a security risk because the default password is just a placeholder and is easily guessable.
Bug 2. In `docker-compose.yml`, the `icinga2` service had a poorly written conditions for startup. Originally it waited 5 seconds to start up, which could cause `icingaweb` and `director` services to restart constantly if initialization script takes a little longer to finish than normally. There is a comment by the developer: "Please note this needs a more sophisticated solution". The solution was to create a healthcheck on the `init-icinga2` container, and then make a condition on `icinga2` container to make sure the `init-icinga2` is finished. 
Bug 3. `icingaweb` and `director` share the same storage volume `icingaweb:/data`. The `icingaweb` container is the one which creates this storage volume and writes data on it. The `director` then uses this data for its functions. If `icingaweb` doesn't write the data on time, `director` crashes and needs to be restarted. To fix this, I added a condition on the `director` container to wait for the `icingaweb` container to finish its work.
Upgrade 1. Added a `.env` for storing sensitive passwords. In this file, all of the important passwords such as API or database passwords are stored and the `docker-compose.yml` uses variables from this file. This way, the passwords are not hardcoded and exposed, plus it is easier to manage them, since they are in one place.
