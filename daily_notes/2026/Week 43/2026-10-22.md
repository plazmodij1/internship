Today I worked on the development environment. My coach told me to figure out how to bring both Icinga and NetBox from HTTP to HTTPS protocol.
### Progress:
<!--What got done:
	Key takeaways: [what was learned from the research/practice/work? What worked?]-->
With a quick google search, I realised that NetBox doesn't have a direct support for HTTPS protocol, rather they encourage users to setup a reverse proxy with Nginx or Apache. On the other hand, Icinga supports both native HTTPS and a reverse proxy setup for Icingaweb. Since I have to setup a reverse proxy for NetBox, I figured it is better to do the same for Icinga. I decided to use Nginx for my reverse proxy since I am already familiar with it. NetBox has a step by step guide on their official documentation on how to setup a reverse proxy so I used that. The only difference is their setup is for NetBox running on an actual server and not in a Docker container so I had to modify a few things. First, as the tutorial suggests, I generated the SSL key and cert myself because it is good enough and it is pointless to get a signed certificate for a local development. Next, I created a Nginx `.conf` file to configure the Nginx server. I followed this tutorial: https://www.scaleway.com/en/docs/tutorials/nginx-reverse-proxy/ and modified it a bit to fit my needs. Next, in the `docker-compose.yml` file I added a service for the reverse proxy, exposed the port 443 and attached the config file and the folder which contains the SSL certificate and key. After verifying the reverse proxy works and that I can access NetBox through HTTPS protocol, I went on to do the same for Icingaweb. The process was the same, I generated the SSL key and certificate and added the Icingweb to Nginx' `.conf` file. Since I am using a master `docker-compose.yml` file, I didn't need to create another Nginx server. All I did is I attached the Icinga's compose file to this master file and let Docker handle the rest. After starting the containers, I verified that Icinga can be accessed and I was finished with this assignment. Currently, I have both NetBox and Icinga running on only HTTPS, making it more secure and one step closer to production setup.
### Blockers:
<!-- Issue:
Solution/Status:-->
As much as the process described above sounds straight forward, there where two main issues I encountered. The first issue was after setting up the reverse proxy. When I started the Nginx container, it crashed immediately. When I checked the logs, I saw it couldn't access the SSL key and cert. After looking at the official documentation of Nginx on where it stores its SSL certificates and the custom config file, I realised I had a typo in the compose file. Docker was looking for a folder called `SSL` on my machine, but I named it `SLL`. Fixing the typo finally fixed the issue and I managed to access NetBox. Then, I decided to add Icinga to the reverse proxy and that's where the second issue appeared. The issue was the structure of my project. My project has a main compose file and two folders, one for Icinga and the other for NetBox. Initially I created the reverse proxy in the NetBox folder, but I realised that makes no sense since I also need it for Icinga, so I moved the reverse proxy to the root of the project where the main compose file is. This wasn't a problem, but the issue occurred when I started both Icinga and NetBox. Both Icinga and NetBox where running but I couldn't access them trough the proxy. I was just getting the 502 error and I couldn't figure it out. I asked AI for help and we did the troubleshooting. I made sure I put correct ports in Nginx `.conf` file for both services. Then I realised I put the URL for Icinga as "http://icinga.localhost" and this turned out to be a problem since the container for Icinga webserver is not called `Icinga`, but `Icingaweb`, yet the issue was still there. I looked at the logs of both containers and I saw they couldn't reach their appropriate databases, which wasn't a problem before. Initially, because I switched to one main compose file, I though the issue was that NetBox and Icingaweb containers where being created before their database containers. So, I checked the compose file of both services and made sure that both containers weren't created before their databases. Then, I realised the issue was the network variable in the compose files. The issue is, since I am using one main compose file, I had to attach Icinga, NetBox and reverse proxy to the same network. But this created an issue where Icinga and NetBox were isolated from the "default" network other containers such as database were using. So the solution was simple, I just attached them to the default network and the issue was resolved.
