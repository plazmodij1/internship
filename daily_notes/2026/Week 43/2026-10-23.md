Today I looked through the official documentation of NetBox and Icinga APIs. I was researching how to access both service's APIs and how to properly execute requests on them. NetBox requires an API token for it to accept any kind of requests. This is important because it means that Ansible cannot work until the API token is created. So, when the environment is ran for the first time, there is some manual work needed. I am going to look into if it is possible to create this API token through Docker by connecting to the NetBox container and exectuing appropriate command. This is not mandatory but I would like for the environment to be completely automated if possible. For Icinga, it is much more simpler. It just needs a username and password which can be configured in `.env` file before creating the container. The only *issue* which I encountered is that the API calls also need a SSL certificate for them to work. There is a workaround when doing a `curl` request, which requires putting flag `-k`, which bypasses the certificate check. This is great for testing, but since this is a proof of concept, at some point this needs to be addressed. 
I also planned how I want the whole synchronization system to go. I will be utilizing WebHooks on NetBox to trigger Ansible when a change is made. This way, Ansible doesn't need to constantly check the state of NetBox. I also looked into the possibility of creating a database for tracking the success and progress of changes, which would be useful if an error occurs while Ansible is running, or if someone makes changes on Icinga manually. While this is a good solution, it is not part of the MVP, so I will not be doing any further research on this.
