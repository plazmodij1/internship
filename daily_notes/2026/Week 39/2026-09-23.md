Today I made a lot of progress regarding my understanding of the source of truth. I have read a lot of articles which helped me gain a better understanding of what it is, how to implement it in a existing environment, what are its benefits, and what things to consider when implementing it. I found out that the source of truth can contain two types of data: intended and current state of the environment. While both are possible, the best practice is to use it as an intended network state. This allows other automatization tools to extract the data from it, and create an environment you want. I also found out that there isn't one tool to do it all. by that i mean, one SoT tool is good for having custom data attributes, while another one is good for integrating with version control. Because of this, the best practice is to have multiple SoTs for different types of data. For example, for state data you will use an SoT such as Netbox to store it, for configuration files, you would use Ansible, and for operational state you would use monitoring systems. This system allows the data to be decentralised, but also prevents data conflicts. 
While my research is not complete, this gave me a good idea of where I need to go with my research and on what I need to focus on.
